# 鼎新 Workflow ERP Windows 端報表自動化工具

用 [pywinauto](https://github.com/pywinauto/pywinauto) 操作**鼎新 Workflow(Digiwin Workflow)
ERP** 的 Windows 用戶端(舊版 Delphi VCL 介面),把「登入 → 開啟報表查詢畫面 → 填條件 → 送出
查詢 → 排入佇列 → 批次匯出 Excel」這一連串手動操作自動化。之所以走這條路,是因為這套 ERP
沒有開放 API、也沒有唯讀資料庫連線權限可以直接下 SQL 撈資料——只能從 Windows 用戶端的畫面
操作下手。

這是實際在公司內部使用中的自動化流程,抽掉了「跟哪一家公司、哪一份 Excel 報表格式綁定」的
部分之後整理出來的通用工具部分,給同樣在用鼎新 Workflow ERP、想省下手動點報表時間的人參考。

```
Windows 認證管理員(Credential Manager)
        │ 讀帳密,不寫死在程式碼裡
        ▼
啟動並登入 ERP 主程式(MainMenu.exe)
        │
        ▼
Stage A — 批次查詢(run_all_reports.py)
  依序呼叫每個 report_*.py:
  開報表查詢畫面 → 填條件 → 送出 → 排入「佇列工作管理員」
        │
        ▼
Stage B — 批次匯出(part4_batch_export_excel.py)
  打開佇列工作管理員 → 逐一匯出成 Excel 檔
  存到 ERP 固定的匯出資料夾(C:\My Documents)
        │
        ▼
(不在這個工具範圍內:把 Excel 檔案內容貼進自己的追蹤表/報表——
 依每個人自己的業務邏輯另外處理)
```

## 這個工具能做什麼

- **登入**:從 Windows 認證管理員(Credential Manager)讀帳密,啟動 ERP 主程式並自動登入,
  不需要把帳密寫在程式碼或設定檔裡。
- **開啟報表查詢畫面**:用報表代號(例如 `IDLR68`)直接跳轉到查詢畫面,不用在選單裡一層層點。
- **自動填查詢條件**:日期區間(含民國年格式轉換)、下拉選單、checkbox、分頁切換(含
  Ctrl+Tab 切到「進階選項」這種需要組合鍵才會顯示的分頁)。
- **送出查詢並排入佇列**:確認彈窗、把報表排進「佇列工作管理員」。
- **批次匯出 Excel**:打開佇列工作管理員,把排隊中的報表一個個匯出成 Excel 檔,處理過程中
  會遇到的各種視窗(確認框、另存新檔對話框、MDI 子視窗被系統重新掛到別的父視窗底下……)。

## 這個工具「不」包含什麼,以及為什麼

原本的完整流程還有兩段:一段是把匯出的 Excel 報表,依照公司內部特定的活頁簿欄位/工作表
結構貼進對應的追蹤表(例如出貨排程、庫存彙總);另一段是清空/重置那些追蹤表用的暫存檔案。

這兩段被刻意排除在外,因為它們完全綁死在特定公司內部的 Excel 檔案結構(工作表名稱、欄位
對應、彙總邏輯)上,對外沒有參考價值,而且會洩漏內部作業細節。所以這裡分享的只到「報表
查詢 + 匯出成 Excel 檔」為止;匯出的 Excel 檔案要怎麼進一步處理,是每個人自己的業務邏輯,
不在這個工具的範圍內。

換句話說:這裡是「兩段式」的前半段——

1. **Stage A — 查詢報表**(`run_all_reports.py` 呼叫各個 `report_*.py`):登入、逐一開啟每種
   報表的查詢畫面、填條件、送出查詢、排入佇列。
2. **Stage B — 批次匯出**(`part4_batch_export_excel.py`):打開佇列工作管理員,把排隊中的
   報表批次匯出成 Excel 檔,存到 ERP 用戶端限定的匯出資料夾(`C:\My Documents`,這是 ERP
   本身固定的路徑,不是可以自訂的設定)。

後續「Excel 檔案匯出之後要怎麼處理」的部分,请自行依照自己的業務需求撰寫。

## 檔案說明

| 檔案 | 內容 |
|---|---|
| `part2_inspect.py` | 核心共用函式庫:登入、視窗/控制項尋找(pywinauto 包裝)、checkbox 讀取/設定、F2 搜尋清單選取、螢幕截圖、民國年日期格式化、送出查詢等。其他所有腳本都是建構在這支之上。 |
| `part2_reportview_probe.py` | 報表檢視視窗(閱覽報表)的工具列/關閉按鈕座標偵測邏輯,含當初除錯過程的完整記錄(留著給有興趣了解「怎麼一步步除錯出這個座標/邏輯」的人參考)。 |
| `part3_export_excel_probe.py` | 單一報表匯出 Excel 的流程(對照 `part4` 批次版本前的單筆版本,可當作理解批次版邏輯的基礎)。 |
| `part4_batch_export_excel.py` | 批次匯出:打開佇列工作管理員、逐一匯出所有排隊中的報表。 |
| `pipeline_flags.py` | 一個全域旗標(是否要截圖存證),给需要「靜默執行、不留截圖」的排程情境用。 |
| `run_all_reports.py` | Stage A 的入口:登入一次、依序呼叫下面所有 `report_*.py` 的查詢邏輯,單一報表失敗不會中斷其他報表。 |
| `report_idlr16.py` / `report_idlr17.py` / `report_idlr68.py` / `report_idlr69.py` / `report_invr18.py` / `report_mocr10.py` | 個別報表的查詢條件填寫邏輯,每支對應鼎新 ERP 的一個報表代號。 |

`report_idlr68.py` 額外附了一段筆記:原本「查詢起始日=當月1號」的直覺寫法,如果下游有任何
流程會把報表結果**累積成長期歷史清單**,會有資料被永久跳過、事後補不回來的風險,以及可以
怎麼修正(固定錨點起始日,而不是每次都用「當月1號」)。這是一個跟這家公司無關、任何人做
類似的「定期抓報表、下游累積歷史」的自動化都可能踩到的坑,所以特別留著。

`report_invr18.py` / `report_idlr69.py` 裡的庫別代號(`WH01`、`WH02`……)是替換過的示意代號,
不是原始的真實庫別代號——原始代號是這家公司 ERP 裡自己設定的庫別名稱,對外沒有參考價值,
所以換成通用的 `WH01`~`WH08` 佔位符。使用時請自行對照你自己 ERP 畫面上「選擇庫別」下拉/清單
裡實際的代號替換掉。

## 技術上比較有意思的幾個坑

- **Owner-drawn 表格/工具列**(`TDSUCwwDBGrid`、`TDSUCToolBar` 等):這套 ERP 的部分控制項是
  自己畫出來的,不是標準 Windows 控制項,沒有一般的 Control ID/Automation 屬性可以抓,
  checkbox 狀態也不能直接用 `BM_GETCHECK` 讀,得靠像素採樣或座標點擊搭配二次驗證。
- **MDI 子視窗被動態 reparent**(`SetParent`):報表檢視視窗有時會從獨立的頂層視窗被系統轉掛
  成主視窗的 MDI 子視窗,導致「用頂層視窗清單去找」會突然找不到它,得改成從它已知的父視窗
  往下找子孫視窗。
- **`set_edit_text()` 不會真的移動鍵盤焦點**:用這個方式(送 `WM_SETTEXT`)填欄位,畫面看起來
  值填對了,但鍵盤焦點其實還停在原地,如果後面接著送組合鍵(例如 Ctrl+Tab 切分頁),行為會
  跟「真人打字後鍵盤焦點自然停在該欄位」不一樣,得額外呼叫 `.set_focus()`才會一致。
- **`win32gui.PostMessage()` 送 `WM_CLOSE` 是非同步的**:視窗不會馬上關閉,後續動作如果沒有
  先確認視窗真的消失,會抓到還沒關閉的舊視窗而出錯。

## 使用前要調整的地方

1. **`part2_inspect.py` 最上面兩個常數**,可以直接改原始碼,也可以不改程式碼、改成設定同名的
   環境變數(方便不同電腦、不同安裝路徑共用同一份程式碼):
   ```python
   CRED_TARGET = os.environ.get("CRED_TARGET", "DigiwinERP")          # Windows 認證管理員裡,你自己存的那筆帳密的「網際網路或網路位址」名稱
   ERP_EXE = os.environ.get("ERP_EXE", r"C:\Conductor\C_dsbin\MainMenu.exe")   # 你的鼎新 ERP 主程式路徑
   ```
2. 事先在 Windows 認證管理員(控制台 → 使用者帳戶 → 認證管理員 → Windows 認證)新增一筆
   「一般認證」,網際網路或網路位址填上面 `CRED_TARGET` 的值,使用者名稱/密碼填你的 ERP
   帳密。
3. 報表代號(`IDLR68` 之類)、查詢欄位名稱、下拉選單選項、庫別代號,都要換成你自己 ERP 裡
   實際的報表跟欄位——這些是每家公司 ERP 客製化程度不同、一定要自己對照畫面調整的部分,不
   能直接套用。
